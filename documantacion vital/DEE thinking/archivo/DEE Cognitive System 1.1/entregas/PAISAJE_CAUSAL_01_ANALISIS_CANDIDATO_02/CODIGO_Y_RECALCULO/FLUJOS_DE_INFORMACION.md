# Quién aporta información y quién transforma la respuesta

| Flujo | Papel externo declarado | Transformación atribuible a DEE | Límite |
|---|---|---|---|
| A/B espacial | El entorno elige una posición física y proporciona portadores; no envía «cerca/lejos» en la prueba | Encuentros, rutas y un marcador adquirido condicionan la firma posterior | El marco y las oportunidades son preparados; no perspectiva general |
| Señal docente | El instructor aporta X mediante una señal común a todas las oportunidades, sólo durante enseñanza | La experiencia determina qué encuentro conserva una forma utilizable | No se atribuye al ente el diseño de la geometría o del currículo |
| Lector 2L | El instrumento conoce la dosis que suministró y comprueba el incremento | El X nativo adquirido selecciona el token; el parámetro ambiental no entra en esa selección | Es transducción instrumental, no aprendizaje del decoder |
| Magnitud | El entorno suministra la magnitud y el formato; el auditor compara con la referencia sólo para puntuar | El aparato nativo usa la referencia adquirida y modula señales anteriores | No cardinalidad ni comparación resuelta por Python |
| Lector transformado | El investigador prepara una ruta y un aporte fijo con X; selecciona externamente ese acceso | Una historia adquirida produce la influencia que puede encontrarse con el aporte y causar una acción | Reconocimiento condicionado asistido; el aporte X no es reconstrucción autónoma de cualquier contenido |
| Comunicación | Se ofrecen canales, un receptor y oportunidades fijas; el usuario puede pedir un token conocido | El contenido viaja y se transforma en el mismo Runtime, modificando una función receptora | Ni selección autónoma de destinatario ni nueva percepción semántica de B |
| Atlas y recálculo | El auditor lee microestados y calcula diferencias después de las trayectorias | No se atribuye este cálculo al ente | Los archivos del auditor no alimentan la respuesta; CLI normal no puede leerlos |
| Gestión | El usuario elige una vida/perfil y una operación explícita | Continúa el mismo estado completo o una bifurcación identificada | El gestor no busca quién sabe el target ni devuelve futuros explorados en copias |

Los metadatos conservan interfaces, fases, agenda y progreso necesarios para continuar. El registro de que se ofreció una fase o una enseñanza no cuenta como adquisición: las lecturas nativas y controles fijan el resultado. Las funciones nuevas no consultan las entradas documentales de experiencias para elegir palabras.

El catálogo de capacidades, NSM65, los resultados esperados y los controles pertenecen a revisión/contratos. No son una tabla de respuestas del participante. La prueba del CLI utiliza la frontera de lectura existente; es una comprobación Python del flujo de archivos, no una afirmación de aislamiento absoluto del sistema operativo.
