# Revisión transversal dirigida

Esta nota registra qué se consultó para decidir contratos y pruebas de Entrega
02. No es un inventario del corpus ni afirma una revalidación científica de las
campañas históricas.

| Fuente | Consulta realizada | Uso en el producto |
|---|---|---|
| Entrega 01 | API, source, tests, fixtures, scripts, documentación e informe técnico del ZIP preservado | compatibilidad de API, snapshot v1 real, fixtures WHL y baseline denso |
| Source/WHL v27 | source canónico y miembro source del WHL con SHA-256 `44a80f...207ab`; identidad del wheel/binario registrada | regla local, `tick_universo`, Lazy, paralelo y oráculos diferenciales |
| Física DEE 4.0.1 | secciones pertinentes de estado completo, tick, observers, memoria, aprendizaje y composición | separación entre estado causal, interfaz, lectura y proyección |
| Procesamiento Nativo DEE | mapa de fuentes y capítulos de fibras, aprendizaje, reprogramación, memoria relativa, historia distribuida y recurrencia | vocabulario y dominio de los siete contratos del catálogo |
| CORE01–14 / Master Revalidation | informe maestro y tabla por familias; los aparatos no se reejecutaron | transporte, reducer/fibra, fase, memoria, aprendizaje e interfaz |
| CORE15–17 | informes finales dirigidos | estado completo, observers, información oculta, identidad funcional y límites de composición |
| Ingenierías 01–06 (incl. 04.5/POST) | referencias y mecanismos seleccionados mediante el tratado/índices; source primario sólo donde fija un builder portado | recurrencia, memoria relativa, contexto distribuido y reutilización; 04.5/POST no se exportan como builders independientes |
| Procesos 01–02 | mecanismos y telemetría ya reducidos en el tratado/índices | historia, contexto, interfaz y testigo multicanal de la Composición B |
| Procesos 03 | identidad del paquete y alcance revisados; no se importó una ley térmica | sin builder ni afirmación térmica en esta entrega |
| PENSAMIENTO 01 | runners concretos de consecuencia/reprogramación, transporte de `s_reg` y retorno usados por los builders | Composición A, bridge y consultas posteriores |
| PENSAMIENTO 02 | índice acumulativo y continuación de preacondicionamiento/autocalibración | controles de corte/sham, ausencia frente a carga cero y límites de recurrencia |

Las descripciones históricas se usaron para localizar mecanismos. La autoridad
de la implementación del tick es el source v27 identificado; la autoridad de
una respuesta histórica es su fixture o telemetría, no el nombre narrativo.
Una capacidad sólo se marca disponible cuando este paquete incluye builder,
contrato, ejecución y prueba. Para CORE05 se recuperaron los runners y locks
primarios NRH04/NRH06; el port versionado y sus oráculos finitos se documentan
en `CORE05_PHASE_MEMORY.md`. Las exploraciones del nuevo laboratorio permanecen
separadas y no se promovieron por el mero hecho de producir telemetría.

## Mapa dirigido de candidatos

Esta clasificación evita convertir una mención histórica en una función del
producto y, a la vez, evita usar el catálogo actual como límite ontológico.

| Mecanismo localizado | Clasificación en esta revisión | Tratamiento |
|---|---|---|
| Memoria por fase NRH04/NRH06 | capacidad respaldada e incorporada | `temporal_phase_memory.core05.v1`, dominio finito |
| Transducción retardo→posición CORE05 | respaldada pero no portada | conservar como candidato de port; no se reconstruyó sin fixture dedicado |
| Repertorios separados CORE07 | respaldados pero no portados como contrato independiente | antecedente de integración; no se renombró el multicanal P02 como repertorio CORE07 |
| Transferencia/actualización C7H03 | capacidad respaldada e incorporada | linaje y bridge versionados, composiciones y controles |
| Reparación/reinstanciación funcional | respaldada históricamente, no portada | requiere contrato de daño, lectura y recuperación propio |
| Accesibilidad y acoplamiento 03–04.5/POST | respaldados pero no portados como builders independientes | usados para límites de compatibilidad; RA01/RA02 no se reinterpretan como positivos |
| Historia distribuida 05–06 | capacidad respaldada incorporada en composición | `distributed_context.i05.v1`, con alcance de su testigo |
| Reutilización finita PENSAMIENTO 01 | capacidad respaldada incorporada parcialmente | puertos/consultas finitas; multiexperiencia general queda como hipótesis |
| Respuesta contextual Procesos 02 | capacidad respaldada incorporada en composición | `contextual_multichannel_recurrence.p02.v1`, sin atribución térmica |
| Retorno ambiental endógeno y enseñanza propia | hipótesis | sólo laboratorio futuro; la consulta nueva ejecutada aquí fue ACOPLADA |
| Fan-out/replicación adquirida | hipótesis | no se exporta; el aparato nuevo produjo un único endpoint |
| Gestión industrial, adapters y operación prolongada | no pertinente a este cierre | reservado para decisiones explícitas de Entrega 03 |
