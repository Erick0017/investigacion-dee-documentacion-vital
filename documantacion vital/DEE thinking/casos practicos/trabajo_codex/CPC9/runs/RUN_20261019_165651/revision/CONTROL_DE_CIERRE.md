# Control técnico de cierre CPC9

Auditoría pasiva anterior al sello; no es todavía verificación del ZIP final. No se creó ni avanzó ningún Runtime.

Se localizaron 268 registros COMMAND y 3 START sin COMMAND (0 de CPC9 sin cancelación explícita; 1 de verificación Core externa). COMPLETED significa fin de proceso: se conservan códigos de salida no cero y resultados adversos. Las esperas de cola y el tiempo de pared no se convierten en CPU. No se midió electricidad.

Se verificaron por streaming 321 checkpoints root: SHA-256 del archivo, CRC gzip y SHA-256/longitud descomprimidos, contrastados con recibos de almacenamiento cuando existen. La integridad de bytes no sustituye reproducción física.

La onda incluyó 73 copias pasivas pre-tick, además de dos forks de corte/sham; no son75 individuos. El fallo de reconstrucción tardía V1 y la revisión V2 con SyntaxError antes del Runtime permanecen; R1 corregida se registró por separado.

E1 sigue siendo una genealogía principal; preparaciones auxiliares, forks y reproducciones técnicas no se suman como conocimientos simultáneos ni réplicas independientes. Los detalles y localizadores constan en RECURSOS_Y_COSTES.json y CONTROL_DE_CIERRE.json. Falta sellar, extraer e instalar el ZIP exacto y ejecutar su comprobación externa.
